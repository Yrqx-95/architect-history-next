# Cross-Product Patterns

Research date: June 7, 2026

## Evidence Base

This synthesis uses direct observations from:

- Linear homepage and Plan page
- Notion localized homepage and Guides index
- Khan Academy homepage and Art History course
- Google Arts & Culture homepage, Explore, and Time
- Are.na homepage and an Architecture & Urban Planning channel

## Pattern 1: One Clear First-Level Promise

- Linear: product development system.
- Notion: integrated workspace.
- Khan Academy: start learning.
- Google Arts & Culture: discover culture.
- Are.na: save, organize, and connect ideas.

Archistory currently communicates archive breadth more clearly than learning direction.

Recommendation:

Use one first-level statement: **Architecture Learning Archive**. Then provide two modes:

- Start learning.
- Explore the archive.

## Pattern 2: Global, Collection, and Object Context

Linear and Notion are strongest at context preservation.

- Global: product or workspace.
- Collection: project, guide topic, or page tree.
- Object: issue, guide, or page.

Khan Academy expresses the same structure as subject, unit, and lesson.

Recommendation:

Archistory should consistently show:

- system: Learn or Explore
- collection: path, period, style, or topic group
- object: term, code topic, building, or architect

## Pattern 3: Density Is Layered

None of the strongest examples make every layer equally dense.

- Linear pairs sparse explanation with dense product evidence.
- Notion accumulates detail vertically.
- Khan groups many links under clear units.
- Google Arts uses images and horizontal groups.
- Are.na uses collection context to hold heterogeneous blocks.

Recommendation:

Do not reduce Archistory content. Layer it:

- first decision
- group
- detail
- related material

## Pattern 4: Plain-Language Starts

Khan Academy’s “Start here” is more effective than a branded feature name. Google uses questions such as “What do you want to discover?” Linear numbers its sequence.

Recommendation:

Use direct labels:

- Start Architecture Student
- Start with Drawing
- Recommended terms
- Continue learning
- Explore related buildings

## Pattern 5: Relationships Need Reasons

Google Arts labels why an artwork is related: same period, movement, collection, material, or visual similarity. Are.na shows where a channel or block appears. Linear shows project and label membership.

Recommendation:

Every Archistory recommendation should state why:

- example of this term
- same movement
- same structural system
- next term in this stage
- related code concept
- building from this period

## Pattern 6: Sequence and Exploration Are Different Modes

- Khan provides sequence.
- Google Arts provides exploration.
- Are.na provides networked association.
- Linear provides state and hierarchy.
- Notion provides readable knowledge containers.

No single reference solves all Archistory needs.

Recommendation:

Use sequence as the entry and exploration as the expansion:

1. Architecture Student tells users where to begin.
2. Glossary and Code explain concepts.
3. Buildings and Timeline provide evidence and context.
4. Related entities open nonlinear discovery.
5. Continue Learning returns users to the path.

## Pattern 7: Cards Are Not the Default Unit

The benchmark products use:

- text lists
- dividers
- rows
- bands
- images
- compact metadata
- occasional cards

Recommendation:

Reserve cards for independently actionable collections or highlighted items. Use lightweight rows and links for stage terms, related concepts, and dense indexes.

## Pattern 8: Visual Identity Follows Product Purpose

- Linear is precise and operational.
- Notion is calm and document-oriented.
- Khan is explicit and instructional.
- Google Arts is visual and exploratory.
- Are.na is neutral and associative.

Recommendation:

Archistory needs a hybrid:

- Linear’s structural precision
- Notion’s reading calm
- Khan’s progression clarity
- Google Arts’ cultural discovery
- Are.na’s network logic

It should not visually imitate any one product.

## Comparative Ranking

| Product | Best Benchmark Role | Relevance to Archistory |
|---|---|---:|
| Khan Academy | Guided learning progression | Very high |
| Google Arts & Culture | Archive exploration | Very high |
| Notion | Knowledge-page hierarchy | High |
| Linear | Density and context discipline | High |
| Are.na | Networked knowledge behavior | High, later-stage |

## Direct Answer

If Archistory becomes an Architecture Learning Archive:

- **Behave like Linear** when organizing navigation levels, alignment, states, and dense metadata.
- **Behave like Notion** when presenting long-form knowledge, terms, code explanations, and reading hierarchy.
- **Behave like Khan Academy** when onboarding learners, naming stages, indicating starts, and guiding the next step.
- **Behave like Google Arts & Culture** when exploring buildings, architects, periods, styles, and visual relationships.
- **Behave like Are.na** when one entity belongs to multiple conceptual collections and users move through related contexts.

It should not copy:

- Linear’s productivity pressure.
- Notion’s blank workspace.
- Khan’s school and mastery identity.
- Google Arts’ endless entertainment browsing.
- Are.na’s beginner ambiguity.
